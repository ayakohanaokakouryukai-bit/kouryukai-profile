# 運用メモ

会の準備から終了後までの、困ったときの対応をまとめています。「データ用スプレッドシート」は、これまで使っていたものと同じで、そこに新しいタブ（`URL作り直し`、`写し_合鍵`、`写し_プロフィール`）があります。

## キャンセルの扱い

回答用スプレッドシートの「キャンセル」列に、何か入力します（○など）。入力すると、GASがすぐCloudflareに伝えます。早ければ数秒、遅くても5分以内に反映されます。反映されたあとは、その人の専用URLも一覧の表示も、すぐ使えなくなります。待たされる時間（キャッシュ）はありません。

同じメールアドレスで回答が複数行ある場合は、すべての行に入力してください（1行でも空だと、登録できる状態のままになります）。

## メールが届かない人

1. 迷惑メールフォルダを確認してもらうようお願いします。
2. それでも届かないときは、データ用スプレッドシートの `写し_合鍵` タブで、その人のメールアドレスの行を探し、専用URLの列をコピーして、LINEなどで本人に直接送ります（このタブは5分ごとに更新されます）。

## 専用URLの作り直し（URLが漏れたとき）

1. データ用スプレッドシートの `URL作り直し` タブを開きます。
2. A列（`メールアドレス`）の空いている行に、その人のメールアドレスを入力します。
3. 少し待つと、B列（`結果`）に `済 <日時>` と出ます。その瞬間から、古いURLは使えなくなります。B列が空のまま、C列に失敗のメモが出たときは、5分以内に自動でやり直されます。
4. 本人に、登録ページでメールアドレスをもう一度入力してもらいます。新しいURLがメールで届きます。作り直しをすると「その日に送った」という記録も消えるので、その日のうちでも届きます。

B列が `見つかりません` のときは、メールアドレスの打ち間違いか、まだ専用URLを発行していない人です。処理済みの行は二度と処理されません。もう一度作り直したいときは、新しい行に入力してください。

## メールアドレスの打ち間違い

回答用スプレッドシートの、メールアドレスを直します。新しいアドレスの人として扱われます。古いアドレスの専用URLとプロフィールは、申込者でなくなるため使えなくなります（引き継がれません）。

## 送信待ちの確認

`写し_合鍵` タブの「送信待ち」の列に「送信待ち」と書かれている行は、メールがまだ送れていない人です。1時間ごとに、頼んでから15分以上たったものが自動で送り直されます。ただし、その日すでにメールを送った人は、翌日にならないと送れません。
1日に送れるメールは100通までです。残りが10通を切ると、運営のアドレスに知らせのメールが届きます。

## 写しのタブについて

`写し_合鍵` と `写し_プロフィール` は、見るためだけのタブです。5分ごとにCloudflareから取ってきて上書きされます。ここで文字を直してもアプリには反映されません。プロフィールの内容を直したいときは、本人にマイページで直してもらってください。

## 申込者の一覧が止まったとき

申込者の一覧が空になる、または今までの半分以下に減る場合、Cloudflareは安全のため受け付けず、前の一覧を使い続けます。同時に、運営のアドレスに知らせのメールが届きます。回答用スプレッドシートの内容（行を消していないか、見出しが変わっていないか）を確かめてください。正しい状態に戻れば、GASの `pushApplicants` を実行するか、5分待てば反映されます。

## 案内の出し方

- 登録ページの案内は、一斉に出さず、数回に分けて出してください（1日に送れるメールが100通までのためです）。

## やってはいけないこと

- `URL作り直し` タブの1行目（見出し）の変更や、並べ替え・列の挿入をしないでください。動かなくなります。
- データ用スプレッドシートを、誰とも共有しないでください。全員の専用URLが載っています。共有ドライブにも入れないでください。
- 古いGASの `processPendingTrigger`（1時間ごとのトリガー）を、また有効にしないでください。メールが二重に送られます。

## 会が終わったあと（2027-05-06以降）

- 2027-05-06 を過ぎると、専用URLは自動で使えなくなります。
- そのあと、データを手作業で削除してください（自動では消えません）。**削除は元に戻せません。必ず、消してよいかを確認してから行ってください。**
  - データ用スプレッドシート：削除します（全員の専用URLが載っているため）。
  - Cloudflareのデータ（D1）：次のどちらかにします。
    - 表ごとに中身を消す方法。`worker` フォルダで、次を1つずつ実行します。

```bash
npx wrangler d1 execute kouryukai-profile --remote --command "DELETE FROM photos"
```

```bash
npx wrangler d1 execute kouryukai-profile --remote --command "DELETE FROM profiles"
```

```bash
npx wrangler d1 execute kouryukai-profile --remote --command "DELETE FROM tokens"
```

```bash
npx wrangler d1 execute kouryukai-profile --remote --command "DELETE FROM applicants"
```

    - データベースごと消す方法。`npx wrangler d1 delete kouryukai-profile` を実行します（確認が出ます）。消したあとはアプリが動かなくなります。
  - 古い仕組みのデータ（古いGAS用の `tokens` `profiles` タブ、古い写真用フォルダ）も、確認のうえで削除します。
- 回答用スプレッドシート（フォームの回答）をどうするかは、別途ご判断ください。

## 本番前の確認

### 同時アクセスのテスト

100人が同時に一覧を開いても動くかを確かめます。

1. データ用スプレッドシートの `写し_合鍵` タブで、自分の行の専用URLをコピーし、`#t=` の後ろの文字を合鍵として控えます。ただし、自分のプロフィールで、公開に同意して必須項目を入力済みにしておく必要があります（一覧が開けない状態だと、すべて失敗になります）。
2. ターミナルで、アプリのフォルダに移動します（`cd ` と入力してFinderからフォルダをドラッグすると場所が入ります）。

```bash
cd <profile-appフォルダの場所>
```

3. 次を入力します（`<公開URL>` と `<合鍵>` は置き換えます。公開URLの最後に `/api` を付けます）。

```bash
node tools/loadtest.mjs --url <公開URL>/api --token <合鍵> --n 100
```

結果は `ok=100 failed=0 p50=... p95=... max=...` のように表示されます（単位はミリ秒）。

合格ライン：`failed=0`、かつ `p95` が 1000（1秒）程度以内が目安です。

### 数式・自動変換の確認

プロフィールに入力した文字が、スプレッドシートで数式や数字に変わらないことを確認します。

1. 自分の専用URLで、「今やっていること」などに、次を1つずつ入力して保存します：`=1+1`、`=A2`、`3/4`、`007`、`50%`
2. 5分ほど待って、データ用スプレッドシートの `写し_プロフィール` タブを開きます。

うまくいくと：入力したとおりの文字のまま（`=1+1` が `2` になっていない、`007` が `7` になっていない、`3/4` が日付になっていない、`50%` が `0.5` になっていない）表示されます。

## 元に戻す方法（切り替えをやめるとき）

切り替え（セットアップ手順14）のあとで、古い仕組みに戻したいときの方法です。古い仕組みのGASのウェブアプリと、古いタブ（`tokens` `profiles`）を消していなければ戻せます。

1. ターミナルで `profile-app` フォルダに移動し、`main` にします。

```bash
cd <profile-appフォルダの場所>
```

```bash
git checkout main
```

2. 次のどちらかで、画面の向き先を古いGASに戻します。
   - かんたんな方法：切り替えのときの取り込み（merge）を、まとめて取り消します。`git log --merges` で取り込みの行（`Merge branch 'feat/cloudflare-migration'`）を探し、その `commit` のあとの英数字をコピーして、`git revert -m 1 <コピーした英数字>` を実行します。
   - 手で直す方法：`.github/workflows/pages.yml` の `path: redirect` を `path: web` に戻し、`web/js/config.js` を古いGASのウェブアプリのURLに戻します（`export const GAS_URL = '古いGASのウェブアプリのURL';` の形にし、`web/js/api.js` の先頭の `import { API_URL } from './config.js';` も `GAS_URL` を読む形に戻します）。
3. 保存して、push します。

```bash
GH_TOKEN=$(gh auth token -h github.com -u ayakohanaokakouryukai-bit) git push origin main
```

4. 古いGASのエディタを開き、関数の選択欄で `setupTriggers` を選んで「実行」を押します。これで `processPendingTrigger`（1時間ごと）が戻ります。同時に、新しいGASのトリガー（時計マーク「トリガー」）は全部削除してください。メールが二重に送られます。

うまくいくと：GitHubの「Actions」が緑になり、古いページが、これまでどおりに表示されます。

注意：切り替えのあとに新しい仕組みで入力されたプロフィールや写真は、古い仕組みには写りません（自動では戻りません）。必要なら、`写し_プロフィール` タブを見て手で控えてください。

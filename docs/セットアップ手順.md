# セットアップ手順

アプリを Cloudflare（クラウドフレア）で公開するときの手順です。上から順に進めてください。ターミナル（Macのアプリ）では、書かれたとおりに入力して Enter を押します。費用は0円で、クレジットカードの登録は要りません。

使うアカウント
- Google：`ayako.hanaoka.kouryukai@gmail.com`
- Cloudflare：同じメールアドレスで作ります（手順2）
- GitHub：古い公開ページ（github.io）を新しいページに移動させるためだけに使います

仕組みのおおまかな説明
- 画面と処理とデータは Cloudflare に置きます（Workers と D1 だけを使います）。
- メールの送信と、スプレッドシートとのやり取りだけ、新しい Google Apps Script（GAS）に任せます。このGASは、今まで使っていたもの（`gas/`）とは別のプロジェクトです。今のGASはそのまま残します。

## 1. 事前に必要なもの

次の2つが入っているか、ターミナルで確認してください。

1. Node.js：バージョンが表示されれば大丈夫です。

```bash
node -v
```

2. clasp（Google Apps Script を操作する道具）：入っていなければインストールします。

```bash
npm install -g @google/clasp
```

```bash
clasp --version
```

このMacでは、clasp のログインに `kouryukai` という名前を付けて使います。そのため、clasp のコマンドは `clasp -u kouryukai ...` と書きます（手順4で最初にログインします）。

## 2. Cloudflareのアカウントを作る

1. https://dash.cloudflare.com/sign-up を開きます。
2. 交流会のメールアドレス（ayako.hanaoka.kouryukai@gmail.com）と、新しいパスワードを入力して登録します。
3. 届いた確認メールのボタンを押して、メールアドレスを確認します。
4. 料金の選択が出たら、無料（Free）のままにします。カードの入力は不要です。

うまくいくと：Cloudflareの管理画面（ダッシュボード）が開きます。

## 3. 道具を入れて、Cloudflareにログインする

1. ターミナルで、アプリのフォルダ（`profile-app`）の中の `worker` フォルダに移動します。`cd ` と入力してから、Finderで `worker` フォルダをターミナルにドラッグすると、場所が入力されます。

```bash
cd <profile-appフォルダの場所>/worker
```

2. 必要な部品を入れます。

```bash
npm ci
```

うまくいくと：エラーなく終わります（警告が少し出ても構いません）。

3. Cloudflareにログインします。ブラウザが開くので、手順2のアカウントでログインし、「Allow」（許可）を押します。

```bash
npx wrangler login
```

うまくいくと：ターミナルに「Successfully logged in」と出ます。

## 4. データの置き場所（D1）を作る

1. データベースを作ります。

```bash
npx wrangler d1 create kouryukai-profile
```

うまくいくと：`database_id = "xxxxxxxx-xxxx-..."` という行が表示されます。

2. `worker/wrangler.toml` をテキストエディタで開きます。`database_id = "REPLACE_AT_SETUP"` の `REPLACE_AT_SETUP` を、表示された `database_id` の値（長い英数字）に書き換えて保存します。

3. データベースに表を作ります。

```bash
npm run migrate
```

途中で「Ok to proceed?」と聞かれたら `y` を入力して Enter。

うまくいくと：「✅」の印と、`0001_init.sql` が適用されたという表示が出ます。

## 5. 秘密の合言葉を決める（SYNC_SECRET）

CloudflareとGASが、お互いを確かめるための長い合言葉です。他人に見せず、GitHubにも置きません。

1. 推測されにくい、32文字以上の英数字を作ります。次を入力すると作れます。表示された文字をメモ帳に控えておきます（手順8でGASにも同じものを入れます）。

```bash
openssl rand -hex 24
```

2. Cloudflareに登録します。「Enter a secret value」と聞かれたら、控えた文字を貼り付けて Enter。

```bash
npx wrangler secret put SYNC_SECRET
```

最初に「There doesn't seem to be a Worker called "kouryukai-profile"... create a new Worker」と聞かれたら `y` を入力して Enter。

うまくいくと：「Success! Uploaded secret SYNC_SECRET」と出ます。

## 6. 初めての公開（デプロイ）と、URLの確認

1. 公開します。

```bash
npm run deploy
```

2. 最後のほうに、次のようなURLが表示されます。これがアプリの公開URLです。

`https://kouryukai-profile.<サブドメイン>.workers.dev`

3. このURLをメモ帳に控えます。
4. `worker/wrangler.toml` を開き、`APP_BASE_URL = "REPLACE_AT_SETUP"` の `REPLACE_AT_SETUP` を、そのURLに書き換えて保存します。最後にスラッシュは付けません。

うまくいくと：URLの最後が `.workers.dev` で終わり、スラッシュで終わっていません。まだメール用の設定（`GAS_MAIL_URL`）は仮のままですが、手順9で直します。

## 7. 新しいGAS（メール係）を作る

1. Apps Script API をオンにします（すでにオンなら不要です）。交流会のGoogleアカウントでログインしたまま https://script.google.com/home/usersettings を開き、「Google Apps Script API」をオンにします。
2. clasp にログインします。ブラウザが開くので、交流会のアカウントを選び、「許可」を押します。

```bash
clasp -u kouryukai login
```

うまくいくと：ターミナルに「Authorization successful.」と出ます。

3. `profile-app` フォルダの中の `gas-bridge` フォルダに移動します。

```bash
cd <profile-appフォルダの場所>/gas-bridge
```

4. 新しいプロジェクトを作ります。

```bash
clasp -u kouryukai create --type standalone --title "100人交流会 メール係"
```

うまくいくと：「Created new standalone script」とURLが表示され、`gas-bridge` フォルダに `.clasp.json` ができます。

5. claspが `appsscript.json` を上書きしてしまうことがあります。元に戻します。

```bash
git checkout appsscript.json
```

6. コードをGoogleに送ります。

```bash
clasp -u kouryukai push
```

もし「Manifest file has been updated. Do you want to push and overwrite?」と聞かれたら `y` と入力して Enter。

うまくいくと：「Pushed 5 files.」のように表示されます（数字は多少違っても構いません）。

## 8. GASの設定を入れる

1. GASのエディタをブラウザで開きます。

```bash
clasp -u kouryukai open-script
```

2. 左の歯車「プロジェクトの設定」を押し、一番下の「スクリプト プロパティ」の「スクリプト プロパティを追加」を押します。「スクリプトプロパティ」とは、このアプリだけが読める設定メモのことです。
3. 次の7つを、「プロパティ」と「値」に入力し、「スクリプト プロパティを保存」を押します。

| プロパティ | 値 |
|---|---|
| `WORKER_URL` | 手順6で控えた公開URL（最後にスラッシュを付けない） |
| `SYNC_SECRET` | 手順5で控えた合言葉（Cloudflareに登録したものと同じ） |
| `FORM_SHEET_ID` | 回答用スプレッドシート（参加申込フォームの回答）のID。URL `https://docs.google.com/spreadsheets/d/ここがID/edit` の「ここがID」の部分 |
| `FORM_SHEET_NAME` | 回答のタブ名。例：`フォームの回答 1` |
| `EMAIL_HEADER` | 回答シートのメールアドレス列の見出しを、そのまま |
| `DATA_SHEET_ID` | データ用スプレッドシートのID（これまで使っているものと同じ） |
| `ORGANIZER_EMAIL` | `ayako.hanaoka.kouryukai@gmail.com` |

必要なときだけ入れる設定（なくても動きます）
- `CANCEL_HEADER`：キャンセル列の見出し。空なら `キャンセル` として扱います。
- `EXPIRES_AT`：専用URLの期限。空なら `2027-05-06T23:59:59+09:00` として扱います。
- `OLD_PHOTO_FOLDER_ID`：古い写真用フォルダのID。手順12のデータ引き継ぎのときだけ使います。

うまくいくと：7行（必要なら加えた分も）が一覧に並びます。

重要：データ用スプレッドシートは、誰とも共有しないでください。全員の専用URLが載っているためです。

4. 左の「エディタ」（`<>` のマーク）に戻ります。ファイル一覧で `Main.gs` を開き、関数の選択欄で `setupTabs` を選び、「実行」を押します。

初回は権限の確認が出ます。自分で作ったスクリプトでは普通に出る画面で、危険ではありません。
- 「権限を確認」を押す → アカウントを選ぶ → 「詳細」を押す → 「（プロジェクト名）（安全ではないページ）に移動」を押す → 「許可」を押す。

うまくいくと：データ用スプレッドシートに、`URL作り直し`、`写し_合鍵`、`写し_プロフィール` の3つのタブが増えます。

## 9. GASを公開して、CloudflareにそのURLを教える

1. GASエディタ右上の「デプロイ」→「新しいデプロイ」を押します。
2. 「種類の選択」の歯車から「ウェブアプリ」を選びます。
3. 「次のユーザーとして実行」は「自分」、「アクセスできるユーザー」は「全員」にして「デプロイ」を押します（権限の確認が出たら、手順8と同じ要領で許可します）。
4. 表示された「ウェブアプリ」のURL（`https://script.google.com/macros/s/.../exec`）をコピーします。
5. ブラウザでそのURLを開くと、`{"ok":true}` と表示されます。
6. `worker/wrangler.toml` を開き、`GAS_MAIL_URL = "REPLACE_AT_SETUP"` の `REPLACE_AT_SETUP` を、コピーしたURLに書き換えて保存します。
7. `worker` フォルダに移動し、もう一度公開します。

```bash
cd <profile-appフォルダの場所>/worker
```

```bash
npm run deploy
```

うまくいくと：ブラウザに `{"ok":true}` と出ます。デプロイが成功のメッセージで終わります。

## 10. 申込者の一覧をCloudflareに送る

1. 回答用スプレッドシートに、「キャンセル」列があるか確認します（なければ、回答シートの1行目の一番右の空きセルに `キャンセル` と入力します）。
2. GASエディタで `Main.gs` を開き、関数の選択欄で `pushApplicants` を選び、「実行」を押します。

うまくいくと：「実行完了」と出ます。失敗したときは、運営のメールアドレスに知らせが届くことがあります（一覧が空のときなど）。

## 11. 動作を確かめる

1. 手順6のURLを、ブラウザで開きます。

うまくいくと：登録ページ（メールアドレスの入力欄）が表示されます。

2. すでに回答用スプレッドシートに載っているメールアドレス（自分のもの）を入れて送信します。

うまくいくと：専用URLのメールが届きます（最大で数分）。届かないときは、迷惑メールフォルダを確かめ、それでも届かないときは運用メモの「メールが届かない人」を見てください。

## 12. これまでのデータを引き継ぐ（1回だけ）

これまで古い仕組みで登録した人のプロフィールと専用URLを、新しい仕組みに移します。

1. 古い写真用フォルダのIDを、GASの `OLD_PHOTO_FOLDER_ID` に入れます（写真がなければ不要です）。
2. 新しいGASのエディタで、関数の選択欄から `migrateFromOldTabs` を選び、「実行」を押します。
3. 完了したら、各自のマイページ（専用URL）を開いて、内容と写真が残っているか確認します。

うまくいくと：「実行完了」と出て、すでに発行した専用URLが、そのまま使えます。

## 13. 自動の仕組みを入れる

1. GASエディタで `Main.gs` を開き、関数の選択欄で `setupTriggers` を選び、「実行」を押します。これは次の4つを登録します。
   - 申込フォームに回答が入ったとき、すぐCloudflareに伝える
   - シートを手で直したとき（キャンセル列、`URL作り直し` タブ）、すぐCloudflareに伝える
   - 5分ごとに、申込者の一覧の送信、URL作り直しの確認、スプレッドシートへの写しを行う
   - 1時間ごとに、送れていないメールを送り直す

うまくいくと：「実行完了」と出ます。左の時計マーク「トリガー」を開くと、`onFormSubmitTrigger`、`onEditTrigger`、`timerEvery5Min`（5分ごと）、`hourlyResend`（1時間ごと）が並びます。5分ほど待つと、`写し_合鍵` と `写し_プロフィール` タブに内容が書き込まれます。

## 14. 切り替え（本番にする）

次の順に行います。

1. 古いGAS（`gas/` から作った、これまでのプロジェクト）のエディタを開きます。左の時計マーク「トリガー」を開き、`processPendingTrigger` を削除します（右端の「⋮」→「トリガーを削除」）。これをしないと、新旧の両方からメールが送られてしまいます。古いGASのウェブアプリと、古いタブ（`tokens` `profiles`）は、新しい仕組みで確認が終わるまで消さずに残します。

うまくいくと：古いGASのトリガー一覧から `processPendingTrigger` がなくなります。

2. `redirect/index.html`、`redirect/me.html`、`redirect/list.html` の3つを、テキストエディタで開きます。それぞれにある `var NEW_ORIGIN = 'REPLACE_AT_SETUP';` の `REPLACE_AT_SETUP` を、手順6の公開URL（`https://kouryukai-profile.<サブドメイン>.workers.dev`、最後にスラッシュなし）に書き換えて保存します。
3. ターミナルで `profile-app` フォルダに移動し、次を1つずつ入力します。

```bash
cd <profile-appフォルダの場所>
```

```bash
git add redirect worker/wrangler.toml
```

```bash
git commit -m "chore: set new origin for redirect pages"
```

このMacでは GitHub CLI の普段のアカウントが別のため、push は次のように交流会アカウントのトークンを指定して行います。

```bash
GH_TOKEN=$(gh auth token -h github.com -u ayakohanaokakouryukai-bit) git push origin main
```

4. GitHubのリポジトリの「Actions」タブを開き、緑のチェックが付くまで待ちます（1〜2分）。赤い✗が出たときは、失敗した実行を開いて「Re-run all jobs」で再実行します。
5. 古いページ（`https://ayakohanaokakouryukai-bit.github.io/kouryukai-profile/`）を開いて、新しいページに移動することを確かめます。専用URLの `#t=...` の部分も引き継がれます。

うまくいくと：古いURLを開くと、自動で `workers.dev` の新しいページに移動します。移動しないときは、「新しいページに移動しました。自動で移動しない場合はこちら」のリンクを押せば移動できます。

6. 参加者への案内は、新しい登録ページのURL（手順6の公開URL）で出します。

## 15. コードを直したとき

- 処理や画面（`worker/`、`web/`）を直したとき：`worker` フォルダで、次を実行します（URLは変わりません）。

```bash
npm run deploy
```

- メール係（`gas-bridge/`）を直したとき：`gas-bridge` フォルダで、次を実行します。

```bash
clasp -u kouryukai push
```

そのあと、GASエディタで「デプロイ」→「デプロイを管理」から今のデプロイを編集し、「バージョン」を「新バージョン」にして「デプロイ」を押します。「新しいデプロイ」を選ぶとURLが変わってしまい、`GAS_MAIL_URL` の書き換えと再公開が必要になります。

- `redirect/` を直したとき：`main` に push すると、自動で公開し直されます（手順14の push のコマンド）。
